# LEKHA Financials (portfolio-terminal): agent guide

Last updated 2026-11-19. Read this first; then `docs/INTEGRATION_AUDIT.md` (why each provider was chosen) and `V3_HANDOFF.md` (history of the V3 build).

## What this repo is now

One origin, three front ends sharing one account, one set of `localStorage` keys (`ptpub.v1.*`) and one backend:

| URL | What | Source of truth |
|---|---|---|
| `/` | **Unified app** (React + shadcn shell, collapsible tree navigation, hosts every V2/V3 panel, company workspace, AI research agent, account center) | `app/` (Vite), built to `public/index.html` + `public/assets/index-*` |
| `/v3` | Five-tab shell (kept live, unchanged) | generated by `scripts/build-v3.mjs` into `public/v3/` |
| `/v2` | Original classic terminal (frozen) | `public/v2/` |
| `/login.html` | React/shadcn sign-in page | `login/` |

The old modular "main" skin (`public/app.js`, `views/`, `core/ui` etc.) was **replaced** at the owner's request ("replace everything with v2/v3"); only what V2/V3 lack was rebuilt natively.

## Unified app architecture (`app/`)

* `app/index.html` loads the **classic engine unchanged** (`/v3/lekha-engine.js`, `lekha-analyst.js`, `lekha-account.js`, `/v2/pt-import.js`, ...) plus two patched copies generated by `scripts/build-app.mjs`: `public/app/lekha-ui.js` (default theme LEKHA Teal) and `public/app/lekha-themes.js` (adds LEKHA Teal / Teal Light). `public/app/classic.css` is V3's CSS with `body` retargeted to `.cx`.
* All classic panels are extracted from `public/v3/index.html` (plus V2's projection panel) into `app/stage.html`, which Vite injects into a hidden `#stage`. React's `PanelHost` **moves** the panel elements into view and back; ids never change, so the engine keeps drawing into them.
* `public/app/shell-bridge.js` is loaded before the engine and provides `window.LEKHA_SHELL` (route/onRoute/go/engineTab) and `LEKHA_SUMMARY`. The classic `setTab("set"|"val")` is redirected to shell routes.
* Engine controls the scripts bind to (prices/news pills, USD/THB, Refresh, sign-in link, tier chip, Customize) live in a **hidden `#engine-bar`**; the React banner mirrors them (`app/src/lib/engine.js`) and proxies clicks. Do not rename those ids.
* Navigation = `app/src/nav.js` (`TREE`). Route keys keep V3's spelling (`portfolio/overview`, `sector/rrg`, ...) because classic modules call `LEKHA_SHELL.go("sector/rrg")`. Pages: `app/src/pages/`.
* Tailwind v4 **without preflight**; a scoped reset covers only the shell (`@scope (.shell) to (.cx)`). Theme tokens: shadcn tokens derive from the classic tokens (`--bg --panel --fg --accent ...`), so all 100 themes restyle shell and panels together.
* Build: `npm run build:app` (runs `scripts/build-app.mjs`, the login build, then the app build). Vercel runs the same. **Generated files are committed**; never hand-edit `public/app/*`, `app/stage.html`, `public/assets/*`, `public/v3/*` (except `public/v3/src/*`).
* Local dev: `.claude/launch.json` config `pt-restore` (port 3477) or `node scripts/dev-server.mjs 3477` with keys from `~/.config/portfolio-terminal/keys.env`. The dev server `require()`-caches API modules: **restart it after editing `api/`**.

## Quick Tour (first-run onboarding, `app/src/tour/`)
* `Tour.jsx` (mounted in `App.jsx`) spotlights real DOM, navigates real routes and waits for each target; `steps.js` lists the steps and their targets (selector functions, with `data-tour` hooks in `Banner.jsx`, `App.jsx` aside and `pages/company.jsx`); `layout.js` is the pure placement maths (tested in `api/_tour.test.js`); `copy.js` (regenerate or edit all ten languages together) carries the copy in all ten languages (the React shell is outside the classic dictionary pipeline, so the tour has its own; keep every language in step, the test enforces it); `store.js` holds the state.
* State `not_started | in_progress | completed | skipped` in `ptpub.v1.app.tour`; finishing also writes `prefs.tour` through `PT_UI.setPref`, so it syncs with the account. Auto-starts for anyone who has not completed or skipped it (existing users included) and resumes if interrupted, except on Plans & billing (`autoStartOn` in `tour/store.js`): the first step is pinned to Overview, so it would move a visitor who came to compare plans; it starts on a later load of another page. Replay: sidebar footer, command palette, Account -> Preferences.
* Adding a step: add it to `STEPS`, add its copy to every language in `copy.js`. A step whose target is missing is skipped, never shown broken.
* **The tour is a ten-step walk (26 Nov 2026), the same on every screen size:** welcome, search, navigation menu, portfolio summary, Monte Carlo, stress test, DCF, the AI analyst (one free question), the answer, then a closing call to action. It orients first (where things are), then shows two advanced tools, because a visitor who has only seen buttons to press has no reason to trust the product. Rules that came from watching it in a browser (Playwright, sampling card and ring geometry every 60 ms):
  * **Nothing travels.** Between steps the card and ring fade in at their new place (`data-busy` hides them while the route changes, `data-settled` enables gliding only after about 380 ms). Never animate a card across the page between routes. Tool steps (`act: true`, mode "coach") dock the card at the bottom right (phones: a sheet) and never dim or block the page; explanatory steps dim and place the card beside the target.
  * **The visitor drives the tools; the tour never runs one for them.** Search and the menu are live coach steps, so the page stays usable while the card points at them. Sim and stress arrive empty: `Tour.jsx` sets `window.LEKHA_TOUR_ACTIVE` for the length of the walk, `lekha-sim.js` and `lekha-analyst.js` skip their own auto-run while it is set, and `LEKHA_SIM.resetForTour({hz:"1Y", paths:10000})` clears any earlier result and selects 10K paths. The visitor presses Run; `armSim`/`armStress` only change the card wording when the result appears. After the walk the flag is cleared and normal auto-run returns. DCF is optional. Next is always the primary button; no step auto-advances except the AI pill step (about 4 s after the answer lands).
  * **The ending has a CTA.** Anonymous visitors get "Create a free account" (`/login.html?mode=signup&from=tour&next=...`), "Keep exploring", "See Premium" (`account/plans`) and "I already have an account"; signed-in users get "Start Exploring" plus "See Premium" when they are not already Premium. The account chunk is loaded through the route's error boundary, so a failed chunk shows a recoverable message instead of a blank page. `from=tour` is read by the login page and attached to `CompleteRegistration` as `signup_from=tour` together with the first-touch UTM tags.
  * **Tracking (Meta, `funnel()` in `pixel.js`):** `TourStart`, `TourStep {step}` (every step shown, so drop-off per step is the funnel), `TourTry {step}` (the visitor used a live control), `TourCta {step, action: signup|login|explore|premium}`, `TourComplete {step, action}`, `TourSkip {step}` (the step they quit on), then the existing `SimRun`, `StressRun`, `ValuationAdjust`, `AnswerSeen`, `WallShown`, `WallClick`, and `CompleteRegistration`. Step ids are lowercase letters only (allow-list regex). Do not add parameters that could carry a ticker, search text or holding.
  * Do not feature the LLM council (no demo branch) and never claim options or derivatives analytics: the product has none (only VIX/VIXEQ and CFTC futures-positioning data views).
* **Load performance (measure before changing it).** Use `DEV_COMPRESS=1 node scripts/dev-server.mjs 3477` (compresses like the CDN; without it transfer sizes are 3-4x too large) and profile with CDP (4x CPU, 1.6 Mbps, 150 ms for a phone). Findings so far: `public/pt-demo.js` was the biggest main-thread cost (it builds every simulated dataset at boot; the calendar is now built once and the output is byte-identical, verify with a hash if you touch it), then `lekha-engine.js` rendering every panel at boot (about 1.7 s on a throttled phone; rendering only the visible tab first is the next big win and is not done). React pages, the palette, dialogs, page help and the tour are lazy chunks. Classic scripts and styles get `?v=<content hash>` from the `stamp` plugin in `app/vite.config.mjs`, and `vercel.json` caches them (and `/assets`) immutably, so a changed file is a new URL. Fonts are self-hosted (Latin only; Vietnamese subsets load for that language). The Meta pixel loads when the browser is idle and queues early events. `vercel.json` pins functions to `hnd1`, next to the Supabase database (ap-northeast-1).
* **Engine boot speed (unified app only).** `public/app/shell-bridge.js` sets `LEKHA_SHELL.lazy`; `scripts/build-v3.mjs` patches the engine so that, when it is set: (1) the seven heavy feeds (rotation, breadth, overbought/oversold, factors, volatility, peers, risk) start through `lazyData()` when a route other than overview/holdings opens (`PT_APP.ensureData`, called from `setRoute`) or at an idle warm-up about 3.5 s after boot; (2) the render functions of panels that are inside the hidden `#stage` (regime, lead, vix, fgi, rotation, RRG, breadth, obos, risk app) return at once until the warm-up sets `LZ.warm`, and the warm-up redraws them so `qLog()` still writes the daily `quant/<day>` document and the summary's regime clause still appears; (3) `buildPortfolioSeries` is memoised. `/v2` and `/v3` never set the flag and behave as before. `pt-demo.js` memoises `buildHistory` per holdings set. Measured on the dev server (CDP 4x CPU, 1.6 Mbps/150 ms): phone usable 5.7 s to 3.5 s, blocking time 3.0 s to 1.0 s; desktop usable 1.34 s to 0.77 s. Any code that reads `S.rot`, `S.breadth`, `S.obos`, `S.factor`, `S.vol`, `S.peer` or `S.risk` must call `PT_APP.ensureData()` first (the warm-up covers the overview). Not done: analyst/projection boot deferral, `/api/auth/me` dedupe.
* **First-visit language prompt** (`app/src/components/LangPrompt.jsx`, rules in `app/src/lib/langprompt.js`, detection in `langdetect.js`, copy in `langprompt-copy.js`, tested in `api/_langprompt.test.js`). When the browser prefers a language we ship and the page is English, a slim strip asks once, in that language; it never switches on its own. One answer per visitor, stored in `ptpub.v1.app.langprompt` and mirrored to account prefs (`langPrompt`). Not shown over a running tour, to automation, when an answer or a saved account language exists. The Quick Tour waits for the answer (8 s cap). Accept sets the tour language, then `PT_I18N.setLang` (saves and reloads after 900 ms). The same component is mounted on `/login.html` (relative imports, inline styles). **Before paid traffic in a new language run `node scripts/warm-i18n.mjs <lang> --url <site>` yourself:** the React shell is translated by an LLM on first use (`POST /api/data/i18n`, cached a year), and the first visitor otherwise pays for about five slow batches. Events: `LangPromptShown/Accepted/Dismissed` with a `lang` param.
* **Meta funnel events** live in `app/src/lib/pixel.js`: `funnel()` allow-lists event names and parameters (step, platform, action), first-touch UTM tags are kept in `ptpub.v1.attr` and attached to every event, and one delegated listener (`watchTools`) counts tool use anywhere. Never send tickers, search text, holdings or e-mail addresses to Meta.
* **Instant company header.** The name comes from the built-in list (`lookupLocal`), the last price seen per symbol is kept in `ptpub.v1.app.lastq` (`lastQuote`, shown dimmed as "last seen ... updating" until the live quote lands), and the search box prefetches the quote and bundle for the top matches while the visitor is still choosing.

## Financial data layer (`api/_fin/`, served at `/api/data/*`)

`FinancialDataService` (`api/_fin/service.js`) is the only thing the UI and the AI agent talk to. Providers never leak their own schemas.

* Schemas + unit policy: `schemas.js` (money in plain currency units, rates as **fractions**, per-share unit `USD/share`; every datum has `meta{source, asOf, kind reported|calculated, freshness realtime|delayed|historical, currency, unit, period, filingDate}`).
* Providers (`providers/`): `sec` (primary fundamentals + filings, keyless), `fred` (macro, keyless), `alpaca` (US quotes/bars), `yahoo` (unofficial fallback + search), `twelvedata`, `finnhub` (optional key), `fmp` (optional key), `alphavantage` (last resort, shares the 22/day budget), `fx` (Frankfurter), `coingecko`, `news` (Yahoo RSS + publisher RSS), `web` (web search and page reader).
* Web research (`providers/web.js`, `searchWeb`/`readWeb` in the service): optional `TAVILY_API_KEY`, `BRAVE_SEARCH_API_KEY` or `SERPER_API_KEY`, otherwise keyless — Brave's results page, Bing News RSS (real snippets and publisher names), Google News RSS and Wikipedia are merged and de-duplicated; `read()` uses Tavily Extract when a key is set, then r.jina.ai, then a direct fetch-and-strip. Cached 10 min (search) and 6 h (page). Disabled in demo runs, whose data is frozen at a past date.
* Chains with fallback: quotes `alpaca → finnhub → fmp → yahoo → twelvedata → alphavantage`; statements `sec → fmp`; profile `fmp → finnhub → sec`; news merges all and de-duplicates; peers fall back to same S&P sector. Unconfigured providers are skipped silently and reported in `meta.attempts`.
* Cache (`cache.js`): memory LRU + shared Supabase table (`pt_av_cache`), TTL per data class, single-flight, stale-on-error. SEC statements are keyed by latest accession number (cached until a new filing appears).
* **Valuation (`api/_fin/valuation/`, tested in `_dcfengine.test.js`, `_dcfpack.test.js`, `_finvaluation.test.js`).** `engine.mjs` is a pure ES module used by BOTH the server (`getValuation` loads it with `import()`) and the browser (`@fin` alias in `app/vite.config.mjs`, used by `app/src/components/valuation/DcfCard.jsx`): the server sends one input "pack" (`pack.mjs` `makePack`) and every slider move is recomputed locally in about 30 ms with no request, by the same code that made the defaults. `vercel.json` `includeFiles` ships the `.mjs` files with the functions. **Industrial companies: FCFF DCF.** EBIT is GAAP operating income (after stock compensation and R&D, nothing added back; rebuilt as pre-tax income plus interest when a filer does not tag it); revenue grows at g1 and fades to terminal growth over 10 years; margin moves to its target over 5; **reinvestment = change in revenue / sales-to-capital** (pooled 5-year change in revenue over change in invested capital, bounded 0.3 to 10), so growth is paid for with capital and asset-light compounders are not capped; tax converges from the effective rate to 25%; terminal value = NOPAT x (1 - gT / ROIC_T) / (WACC - gT), ROIC_T fades toward WACC; mid-year discounting struck at the last fiscal year end and rolled forward by `stub`. **Discount rate:** beta is a 5-year weekly regression against SPY (Blume-adjusted, bounded 0.5 to 2, warnings when uncertain or negative), ERP 4.41% (named constant, not auto-refreshed), cost of debt = risk-free + synthetic-rating spread from interest coverage (Damodaran table, January 2026, in `SPREADS`), weights from market cap and debt including leases. **Equity bridge:** EV + cash + short-term and long-term securities - debt - leases - minorities - preferred, per share on a validated share count. **Financials** (`pack.mjs` `isBalanceSheetFinancial`: sector Financials AND liabilities/assets >= 85% AND revenue/assets < 30%, which keeps Visa and Mastercard on the FCFF model) use **residual income**. Scenarios (bear/base/bull) are data-driven: growth at the 25th/50th/75th percentile of 5 years, margin at the 5-year low / 3-year mean / 5-year high, WACC +/-0.75 points. The response also carries the reverse DCF (`impliedGrowth`, and the margin the price implies in the UI), sensitivity grids are computed in the browser, and the old response keys (`intrinsicPerShare`, `marginOfSafety`, `dcf`, `assumptions`, `impliedGrowth`) are kept for the agent, council and older callers. **Share counts (known data traps):** the SEC cover-page count in the feed is one class only for multi-class issuers and can be years stale (Visa shows a 2010 value), so it is used only when under 460 days old and within 25% of the weighted average; otherwise weighted shares, otherwise net income / EPS, otherwise no per-share value (the total is shown). Known limits: no analyst estimates (none free), no pension deficits, no option-pool dilution beyond weighted diluted shares, one currency, XOM-like filers whose annual facts are missing from the feed are "not applicable", dev prices are stale and dev betas unreliable so scans are method reviews, and the classic `analysis/value` page keeps its own engine and can differ. Never tune constants to make a result look fair; change the method and say so on the page.
* Calculation engine (`calc.js`, tested in `api/_fincalc.test.js`): CAGR, YoY/QoQ, margins, ROE, ROIC, D/E, current ratio, FCF/earnings yield, P/E, EV/EBITDA, PEG, DCF, WACC, CAPM, beta, Sharpe, drawdown, volatility, allocation, portfolio return, TTM. **The LLM never does arithmetic.**
* AI provider: **DeepSeek only** (`api/_llm.js`, `api/_ai/ds.js`). Z.ai/GLM was removed on 2026-11-25 and must not be reintroduced; a stale `ZAI_API_KEY` is ignored. Gemini is used only for document embeddings. Model output is schema-coerced and untrusted text is fenced before it reaches the model.
* AI research agent (`agent.js`, `POST /api/data/agent`): plan tools (rules by default; model only if no symbol is detected) → retrieve → numbered **evidence** → model writes typed claims (`fact|calculated|interpretation|speculation`) citing evidence ids → server verifies ids and checks every number in fact/calculated claims against the cited evidence (otherwise downgraded to interpretation). 18 tools, including `web_search`, `web_read`, `get_transcript` and `get_insider_activity`; company and relationship questions always get web evidence, and one extra retrieval pass runs when the model reports a gap and the web was not consulted. The strict `accept` gate was removed: verification downgrades only the offending claim instead of discarding the whole answer. One LLM call keeps it under Vercel's 60 s limit. The chat loop (`api/_ai/loop.js` + `router.js`) uses the same tools, so `web_search` is available in Fast prefetch and in Deep tool-calling.
* **Actions, memory and inbox (`api/_ai/actions.js`, `memory.js`, `inbox.js`, `alerts.js`).** The chat changes state, not only answers. Tools: `add_to_watchlist`, `remove_from_watchlist`, `get_watchlist` (the `settings/watchlist` document the browser already syncs), `create_alert`/`get_alerts`/`delete_alert` (`ai/alerts`), `save_note`/`get_notes` (`ai/notes`) and `compare_to_portfolio` (the signed-in book). They receive `{ userId }` through `tools.run` and refuse in the demo. Memory (`ai/memory`) stores only explicit statements ("remember that ...", "I do not invest in ..."), at most 60, and is injected as a fenced MEMORY block; it is never inferred from market data. The `alerts` cron (`/api/cron/alerts`, daily 06:10 UTC, Bearer `CRON_SECRET`) checks price and news alerts, earnings within seven days and a 3% move digest, and writes `ai/inbox` because no mail provider exists; the inbox is served at `/api/ai/inbox` and shown on the Inbox page. Upcoming earnings dates need an FMP or Finnhub key; without one the reminder stays silent rather than inventing a date.
* Observability (`obs.js`): per-provider calls/errors/latency, cache hit rate, tool failures; daily rollup in `pt_av_cache` (`fin/stats/<day>`); admin page **Account → Diagnostics** (`GET /api/data/diag`, admins only) also shows token usage from `pt_costs` and which env vars are set (booleans only).
* Routes: `search quote quotes history company profile statements facts filings news earnings estimates peers ratios valuation macro fx calc agent diag` (one function, `api/data.js`; Vercel Hobby allows 12 functions, 10 used).

## Picking a plan without an account (26 Nov 2026)
A plan button on Plans & billing never sends the visitor to another page to sign up. The plan goes in the route (`#/account/plans?plan=paid|premium|free`) and `components/PlanSignup.jsx` opens over the page (sign up, sign in, confirm e-mail, reset password); a signed-in account in `?demo=1` leaves the demo instead. After sign-in the app reloads as the account and the Plans page carries on to checkout, the billing portal or a "you already have it" message (`nextStep` in `lib/planIntent.js`, tested by `api/_planintent.test.js`). The choice is also kept in `ptpub.v1.app.planIntent` for one hour so it survives the e-mail confirmation round trip through `/login.html`; it is consumed only at the moment of leaving for Stripe because `pt-state.js` can reload the page first (`PT_SYNC.first`). The Quick Tour does not auto-start on a page load that began this way. Production requires e-mail confirmation, so a new account reaches checkout after opening the e-mail link.

## Product analytics (PostHog, added 2026-11-25)
One script, `public/pt-analytics.js`, is loaded by `/`, `/v2`, `/v3` and `/login.html`; it reads `GET /api/ph` (env `POSTHOG_KEY`, `POSTHOG_HOST`) and initialises the vendored `public/vendor/posthog.js` with autocapture, session replay (typed input masked, screen text readable), heatmaps, exceptions, web vitals and manual pageviews. `app/src/lib/analytics.js` wraps it for React. Server events go through `api/_ph.js` (`api_request` in `api/_router.js`, `subscription_synced` in the Stripe webhook). Event names, privacy rules and setup: `docs/ANALYTICS.md`. Without a key everything is a no-op. Never send e-mails, prompts, questions, search text, holdings or balances.

## Findings from the audit (2026-11-19)
See `docs/INTEGRATION_AUDIT.md`. Headlines: three overlapping price paths and no shared schema; implicit units; cache without policy or hit-rate accounting; `ai/ask` was portfolio-only (no price/news/filings/macro tools, no citations); no provider health view; the contact-less SEC User-Agent in `_edgar.js` (fixed to use `SEC_USER_AGENT`); AV budget shared with existing features. No FMP/Finnhub keys exist locally or (per notes) in production, so everything defaults to free providers.

## Rules
* **House style: clean and professional.** This is a tool for financial professionals. No emoji, emoticons, stickers, confetti, mascots or decorative pictographs anywhere: UI copy, status messages, review flags, e-mails, documents and anything a model writes. Use plain text, the existing line icons (`lucide-react`) and typographic symbols (arrows, triangles for price direction, the middle dot). Copy is neutral and precise: no exclamation marks, no jokes, no shouting in capitals. `api/_style.test.js` fails the build if a pictograph appears in the site's code (including `\uXXXX` escapes); `api/_llm.js` tells every model call the same rule and strips pictographs from model output.
* Do not add a paid provider without checking free tier, limits, display licensing and redistribution (table in the audit). Yahoo is **personal-use only**: replace before a commercial launch.
* Keys are server-side only. Add new ones to `keys.env.example` (the repo's `.gitignore` ignores `.env*`, so the template file is `keys.env.example`).
* New UI uses shadcn components in `app/src/components/ui`. Format numbers with `app/src/lib/fmt.js`; show provenance with `SourceTag`; use `DataState`/`ErrorBox`/`EmptyBox` for loading/error/empty.
* Tests: `npm test` runs every `api/*.test.js`. `api/_i18n.test.js` was already failing on origin/main (requires a moved file). Run `node api/_fincalc.test.js api/_finservice.test.js api/_finagent.test.js` after touching `api/_fin/`.
* Commits: author as the project owner; add the Claude co-author trailer. Deploy per the infra memory (Vercel CLI, assistantforyou account).

## Known gaps / next steps
1. Estimates, price targets and transcripts need an optional `FMP_API_KEY` or `FINNHUB_API_KEY` (code is written and dormant).
2. Intraday data, trades, options, WebSockets: not added (Massive/Polygon only worth it if those become features).
3. Historical valuation series and a stock screener (FMP screener provider method exists, no UI).
4. Non-US fundamentals: SEC covers IFRS (20-F/40-F) as well as US-GAAP (10-K/10-Q), in the filer's reporting currency. Quarterly figures for 20-F filers are still missing, because 6-K filings rarely carry tagged facts.
5. Diagnostics counters are per serverless instance; add a durable log table if cross-instance accuracy matters.
6. Translate the new React screens (the classic panels are translated by `PT_I18N`; the shell is English-first, the i18n observer translates matching strings).
7. Legal text is a draft for counsel review.
8. Playwright smoke test over every route in `nav.js` (a manual sweep was done 2026-11-19).
