# LEKHA Financials (portfolio-terminal): agent guide

Last updated 2026-11-19. Read this first; then `docs/INTEGRATION_AUDIT.md` (why each provider was chosen) and `V3_HANDOFF.md` (history of the V3 build).

## What this repo is now

One origin, three front ends sharing one account, one set of `localStorage` keys (`ptpub.v1.*`) and one backend:

| URL | What | Source of truth |
|---|---|---|
| `/` | **Unified app** (React + shadcn shell, collapsible tree navigation, hosts every V2/V3 panel, company workspace, AI research agent, account center) | `app/` (Vite), built to `public/index.html` + `public/assets/index-*` |
| `/v3` | Five-tab shell (kept live, unchanged) | generated by `scripts/build-v3.mjs` into `public/v3/` |
| `/v2` | Original classic terminal (frozen) | `public/v2/` |
| `/login.html` | React/shadcn sign-in page | `login/` |

The old modular "main" skin (`public/app.js`, `views/`, `core/ui` etc.) was **replaced** at the owner's request ("replace everything with v2/v3"); only what V2/V3 lack was rebuilt natively.

## Unified app architecture (`app/`)

* `app/index.html` loads the **classic engine unchanged** (`/v3/lekha-engine.js`, `lekha-analyst.js`, `lekha-account.js`, `/v2/pt-import.js`, ...) plus two patched copies generated by `scripts/build-app.mjs`: `public/app/lekha-ui.js` (default theme LEKHA Teal) and `public/app/lekha-themes.js` (adds LEKHA Teal / Teal Light). `public/app/classic.css` is V3's CSS with `body` retargeted to `.cx`.
* All classic panels are extracted from `public/v3/index.html` (plus V2's projection panel) into `app/stage.html`, which Vite injects into a hidden `#stage`. React's `PanelHost` **moves** the panel elements into view and back; ids never change, so the engine keeps drawing into them.
* `public/app/shell-bridge.js` is loaded before the engine and provides `window.LEKHA_SHELL` (route/onRoute/go/engineTab) and `LEKHA_SUMMARY`. The classic `setTab("set"|"val")` is redirected to shell routes.
* Engine controls the scripts bind to (prices/news pills, USD/THB, Refresh, sign-in link, tier chip, Customize) live in a **hidden `#engine-bar`**; the React banner mirrors them (`app/src/lib/engine.js`) and proxies clicks. Do not rename those ids.
* Navigation = `app/src/nav.js` (`TREE`). Route keys keep V3's spelling (`portfolio/overview`, `sector/rrg`, ...) because classic modules call `LEKHA_SHELL.go("sector/rrg")`. Pages: `app/src/pages/`.
* Tailwind v4 **without preflight**; a scoped reset covers only the shell (`@scope (.shell) to (.cx)`). Theme tokens: shadcn tokens derive from the classic tokens (`--bg --panel --fg --accent ...`), so all 100 themes restyle shell and panels together.
* Build: `npm run build:app` (runs `scripts/build-app.mjs`, the login build, then the app build). Vercel runs the same. **Generated files are committed**; never hand-edit `public/app/*`, `app/stage.html`, `public/assets/*`, `public/v3/*` (except `public/v3/src/*`).
* Local dev: `.claude/launch.json` config `pt-restore` (port 3477) or `node scripts/dev-server.mjs 3477` with keys from `~/.config/portfolio-terminal/keys.env`. The dev server `require()`-caches API modules: **restart it after editing `api/`**.

## Quick Tour (first-run onboarding, `app/src/tour/`)
* `Tour.jsx` (mounted in `App.jsx`) spotlights real DOM, navigates real routes and waits for each target; `steps.js` lists the steps and their targets (selector functions, with `data-tour` hooks in `Banner.jsx`, `App.jsx` aside and `pages/company.jsx`); `layout.js` is the pure placement maths (tested in `api/_tour.test.js`); `copy.js` (regenerate or edit all ten languages together) carries the copy in all ten languages (the React shell is outside the classic dictionary pipeline, so the tour has its own; keep every language in step, the test enforces it); `store.js` holds the state.
* State `not_started | in_progress | completed | skipped` in `ptpub.v1.app.tour`; finishing also writes `prefs.tour` through `PT_UI.setPref`, so it syncs with the account. Auto-starts for anyone who has not completed or skipped it (existing users included) and resumes if interrupted. Replay: sidebar footer, command palette, Account -> Preferences.
* Adding a step: add it to `STEPS`, add its copy to every language in `copy.js`. A step whose target is missing is skipped, never shown broken.
* **The tour is a ten-step walk (26 Nov 2026), the same on every screen size:** welcome, search, navigation menu, portfolio summary, Monte Carlo, stress test, DCF, the AI analyst (one free question), the answer, then a closing call to action. It orients first (where things are), then shows two advanced tools, because a visitor who has only seen buttons to press has no reason to trust the product. Rules that came from watching it in a browser (Playwright, sampling card and ring geometry every 60 ms):
  * **Nothing travels.** Between steps the card and ring fade in at their new place (`data-busy` hides them while the route changes, `data-settled` enables gliding only after about 380 ms). Never animate a card across the page between routes. Tool steps (`act: true`, mode "coach") dock the card at the bottom right (phones: a sheet) and never dim or block the page; explanatory steps dim and place the card beside the target.
  * **The tour never waits for the visitor.** Sim and stress are run by the tour itself (`run()` in `steps.js` stops the page's own 100K auto-run, picks 10K paths, presses Run; stress presses its Run button) and the card says "Running ..." until the result is on the page. DCF is optional (`try()` only changes the card wording). Next is always the primary button; no step auto-advances except the AI pill step (about 4 s after the answer lands).
  * **The ending has a CTA.** Anonymous visitors get "Create a free account" (`/login.html?mode=signup&from=tour&next=...`), "Keep exploring" and "I already have an account"; signed-in users get a single "Start Exploring". `from=tour` is read by the login page and attached to `CompleteRegistration` as `signup_from=tour` together with the first-touch UTM tags.
  * **Tracking (Meta, `funnel()` in `pixel.js`):** `TourStart`, `TourStep {step}` (every step shown, so drop-off per step is the funnel), `TourDemo {step}` (sim or stress result shown), `TourTry {step}` (visitor adjusted the DCF), `TourCta {step, action: signup|login|explore}`, `TourComplete {step, action}`, `TourSkip {step}` (the step they quit on), then the existing `SimRun`, `StressRun`, `ValuationAdjust`, `AnswerSeen`, `WallShown`, `WallClick`, and `CompleteRegistration`. Step ids are lowercase letters only (allow-list regex). Do not add parameters that could carry a ticker, search text or holding.
  * Do not feature the LLM council (no demo branch) and never claim options or derivatives analytics: the product has none (only VIX/VIXEQ and CFTC futures-positioning data views).
* **Load performance (measure before changing it).** Use `DEV_COMPRESS=1 node scripts/dev-server.mjs 3477` (compresses like the CDN; without it transfer sizes are 3-4x too large) and profile with CDP (4x CPU, 1.6 Mbps, 150 ms for a phone). Findings so far: `public/pt-demo.js` was the biggest main-thread cost (it builds every simulated dataset at boot; the calendar is now built once and the output is byte-identical, verify with a hash if you touch it), then `lekha-engine.js` rendering every panel at boot (about 1.7 s on a throttled phone; rendering only the visible tab first is the next big win and is not done). React pages, the palette, dialogs, page help and the tour are lazy chunks. Classic scripts and styles get `?v=<content hash>` from the `stamp` plugin in `app/vite.config.mjs`, and `vercel.json` caches them (and `/assets`) immutably, so a changed file is a new URL. Fonts are self-hosted (Latin only; Vietnamese subsets load for that language). The Meta pixel loads when the browser is idle and queues early events. `vercel.json` pins functions to `hnd1`, next to the Supabase database (ap-northeast-1).
* **First-visit language prompt** (`app/src/components/LangPrompt.jsx`, rules in `app/src/lib/langprompt.js`, detection in `langdetect.js`, copy in `langprompt-copy.js`, tested in `api/_langprompt.test.js`). When the browser prefers a language we ship and the page is English, a slim strip asks once, in that language; it never switches on its own. One answer per visitor, stored in `ptpub.v1.app.langprompt` and mirrored to account prefs (`langPrompt`). Not shown over a running tour, to automation, when an answer or a saved account language exists. The Quick Tour waits for the answer (8 s cap). Accept sets the tour language, then `PT_I18N.setLang` (saves and reloads after 900 ms). The same component is mounted on `/login.html` (relative imports, inline styles). **Before paid traffic in a new language run `node scripts/warm-i18n.mjs <lang> --url <site>` yourself:** the React shell is translated by an LLM on first use (`POST /api/data/i18n`, cached a year), and the first visitor otherwise pays for about five slow batches. Events: `LangPromptShown/Accepted/Dismissed` with a `lang` param.
* **Meta funnel events** live in `app/src/lib/pixel.js`: `funnel()` allow-lists event names and parameters (step, platform, action), first-touch UTM tags are kept in `ptpub.v1.attr` and attached to every event, and one delegated listener (`watchTools`) counts tool use anywhere. Never send tickers, search text, holdings or e-mail addresses to Meta.
* **Instant company header.** The name comes from the built-in list (`lookupLocal`), the last price seen per symbol is kept in `ptpub.v1.app.lastq` (`lastQuote`, shown dimmed as "last seen ... updating" until the live quote lands), and the search box prefetches the quote and bundle for the top matches while the visitor is still choosing.

## Financial data layer (`api/_fin/`, served at `/api/data/*`)

`FinancialDataService` (`api/_fin/service.js`) is the only thing the UI and the AI agent talk to. Providers never leak their own schemas.

* Schemas + unit policy: `schemas.js` (money in plain currency units, rates as **fractions**, per-share unit `USD/share`; every datum has `meta{source, asOf, kind reported|calculated, freshness realtime|delayed|historical, currency, unit, period, filingDate}`).
* Providers (`providers/`): `sec` (primary fundamentals + filings, keyless), `fred` (macro, keyless), `alpaca` (US quotes/bars), `yahoo` (unofficial fallback + search), `twelvedata`, `finnhub` (optional key), `fmp` (optional key), `alphavantage` (last resort, shares the 22/day budget), `fx` (Frankfurter), `coingecko`, `news` (Yahoo RSS + publisher RSS).
* Chains with fallback: quotes `alpaca → finnhub → fmp → yahoo → twelvedata → alphavantage`; statements `sec → fmp`; profile `fmp → finnhub → sec`; news merges all and de-duplicates; peers fall back to same S&P sector. Unconfigured providers are skipped silently and reported in `meta.attempts`.
* Cache (`cache.js`): memory LRU + shared Supabase table (`pt_av_cache`), TTL per data class, single-flight, stale-on-error. SEC statements are keyed by latest accession number (cached until a new filing appears).
* **DCF defaults (`getValuation` in `service.js`, tested in `api/_finvaluation.test.js`).** The model is a two-stage FCF DCF: growth fades linearly from a starting rate to terminal growth (2.5%) over 10 years. Defaults, all stated on the page: FCF base = mean FCF margin of the last 3 fiscal years x latest revenue (latest fiscal-year FCF only with fewer than 3 years; a non-positive average means "not applicable"); starting growth = median 5-year revenue growth, limited by 12% and by fundable growth (ROIC x net reinvestment where reinvestment = (|capex| - D&A + R&D) / NOPAT averaged over 3 years, never below the terminal rate), floored at 0; discount = WACC with Blume-adjusted beta (clamped 0.6 to 2) and ERP 4.41%, the same inputs as the classic Intrinsic value page. The response also carries `impliedGrowth` (reverse DCF: the starting growth that reproduces the price, or `impliedGrowthNote` "above 40%" / "below -10%"). Known limits: the fundable-growth check understates asset-light, high-return compounders (Visa: 11% revenue growth limited to the 2.5% floor); analyst estimates are not used because none are available without paid keys; the classic `analysis/value` panel has its own scenario engine and can differ. Never tune the constants to make a result look fair; change the method and say so on the page.
* Calculation engine (`calc.js`, tested in `api/_fincalc.test.js`): CAGR, YoY/QoQ, margins, ROE, ROIC, D/E, current ratio, FCF/earnings yield, P/E, EV/EBITDA, PEG, DCF, WACC, CAPM, beta, Sharpe, drawdown, volatility, allocation, portfolio return, TTM. **The LLM never does arithmetic.**
* AI provider: **DeepSeek only** (`api/_llm.js`, `api/_ai/ds.js`). Z.ai/GLM was removed on 2026-11-25 and must not be reintroduced; a stale `ZAI_API_KEY` is ignored. Gemini is used only for document embeddings. Model output is schema-coerced and untrusted text is fenced before it reaches the model.
* AI research agent (`agent.js`, `POST /api/data/agent`): plan tools (rules by default; model only if no symbol is detected) → retrieve → numbered **evidence** → model writes typed claims (`fact|calculated|interpretation|speculation`) citing evidence ids → server verifies ids and checks every number in fact/calculated claims against the cited evidence (otherwise downgraded to interpretation). 13 tools. One LLM call keeps it under Vercel's 60 s limit.
* Observability (`obs.js`): per-provider calls/errors/latency, cache hit rate, tool failures; daily rollup in `pt_av_cache` (`fin/stats/<day>`); admin page **Account → Diagnostics** (`GET /api/data/diag`, admins only) also shows token usage from `pt_costs` and which env vars are set (booleans only).
* Routes: `search quote quotes history company profile statements facts filings news earnings estimates peers ratios valuation macro fx calc agent diag` (one function, `api/data.js`; Vercel Hobby allows 12 functions, 10 used).

## Findings from the audit (2026-11-19)
See `docs/INTEGRATION_AUDIT.md`. Headlines: three overlapping price paths and no shared schema; implicit units; cache without policy or hit-rate accounting; `ai/ask` was portfolio-only (no price/news/filings/macro tools, no citations); no provider health view; the contact-less SEC User-Agent in `_edgar.js` (fixed to use `SEC_USER_AGENT`); AV budget shared with existing features. No FMP/Finnhub keys exist locally or (per notes) in production, so everything defaults to free providers.

## Rules
* **House style: clean and professional.** This is a tool for financial professionals. No emoji, emoticons, stickers, confetti, mascots or decorative pictographs anywhere: UI copy, status messages, review flags, e-mails, documents and anything a model writes. Use plain text, the existing line icons (`lucide-react`) and typographic symbols (arrows, triangles for price direction, the middle dot). Copy is neutral and precise: no exclamation marks, no jokes, no shouting in capitals. `api/_style.test.js` fails the build if a pictograph appears in the site's code (including `\uXXXX` escapes); `api/_llm.js` tells every model call the same rule and strips pictographs from model output.
* Do not add a paid provider without checking free tier, limits, display licensing and redistribution (table in the audit). Yahoo is **personal-use only**: replace before a commercial launch.
* Keys are server-side only. Add new ones to `keys.env.example` (the repo's `.gitignore` ignores `.env*`, so the template file is `keys.env.example`).
* New UI uses shadcn components in `app/src/components/ui`. Format numbers with `app/src/lib/fmt.js`; show provenance with `SourceTag`; use `DataState`/`ErrorBox`/`EmptyBox` for loading/error/empty.
* Tests: `npm test` runs every `api/*.test.js`. `api/_i18n.test.js` was already failing on origin/main (requires a moved file). Run `node api/_fincalc.test.js api/_finservice.test.js api/_finagent.test.js` after touching `api/_fin/`.
* Commits: author as the project owner; add the Claude co-author trailer. Deploy per the infra memory (Vercel CLI, assistantforyou account).
