## Production proposal after separate written approval

- Pin the approved commit, compatible migrations and previous known-good deployment ID. Check backup availability, policy links, commercial data grants and attribution, merchant configuration, allowed destinations, alert routing and incident ownership. Verify Git auto-deployment settings before a merge. The grant reference in an environment setting does not itself establish licensing rights.
- The live Stripe webhook endpoint must subscribe to `checkout.session.completed` and `customer.subscription.created`, `.updated`, `.deleted`, `.paused` and `.resumed`. Staging showed on 2026-11-22 that without `customer.subscription.created` a subscription started outside Checkout (Dashboard, support, API) is paid in Stripe but stays Free in the app until its next update.
- After explicit authorization, merge the reviewed commit and execute the approved release method. Start with a limited cohort. Use read-only application smoke, a preapproved operator test identity, source timestamps, auth-denial behavior and rate/error metrics. Monitor webhook failures, account-entitlement lag, provider fallback and cost, stale data, cron freshness and support contacts. Real customer charges are outside this test plan.
- Stop new sales if entitlements diverge, private data crosses accounts, source rights are in doubt, or billing or AI errors exceed the operator's agreed thresholds. Preserve delivery IDs and logs. Keep the signed webhook available for retries. Restore the known-compatible application deployment, reconcile Stripe against profile state, and verify account and data read paths before reopening. Database rollback or customer data restoration requires a separate reviewed plan. Follow the jurisdiction-specific incident notification procedure where applicable.
