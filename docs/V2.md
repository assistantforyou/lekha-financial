# Portfolio Terminal v2 (`/v2`)

A phone-first rebuild of the front end. Same accounts, plans, Stripe billing, holdings sync and API as the classic terminal
(`/`), a different experience: five screens, almost no scrolling, descriptions collapsed until asked for.

## Who it is for, and how they use it

**Primary audience: self-directed retail investors in Southeast Asia (and anyone similar) who hold US stocks plus local
ones (Hong Kong, Thailand), across several broker apps, and look at the result on a phone.** They are comfortable buying a
stock, but they are not analysts; they want to know *how am I doing, why, and what is coming*.

| Moment | What they do | Where in v2 |
|---|---|---|
| 10-second check (commute, queue) | "Am I up or down, and why?" | **Today**: value, day change, one-sentence reason, biggest movers |
| Something moved | "What is going on with NVDA?" | **Holdings**: tap the row, chart, position, analysts, headlines open right under it |
| Before an event (earnings, Fed) | "Is this already priced in? what could happen to me?" | **Outlook**: events with analyst / media lean, then nine investor personas run on their own holdings |
| Weekly review | "Am I too concentrated? what do analysts think of my stocks?" | **Holdings** allocation bar, **Today** analyst strip, Premium AI chat / briefing / stress test |
| Setup (once) | Add holdings, import broker statements, switch language/currency (USD/THB) | **Me** + Add / Import dialogs |

Design consequences: THB toggle and Thai first-class (language auto-detected), multi-currency holdings, plain words, every
explanation collapsed behind an `i` button, controls always sit directly above what they change.

## Architecture

```
public/v2/            UI of this version (shell, screens, dialogs, css)  -> /v2  (vercel.json rewrite, dev-server)
public/core/          shared by every future version (v3, v4, ...): i18n, data, live prices, charts, council engine, store
public/core/i18n/     generated dictionaries (9 languages); source text in scripts/i18n-v2/*.txt
api/_h/free/quotes.js live quotes   api/_h/free/street.js analysts/headlines/earnings   api/_h/ai/council.js AI explanation
```

* v2 loads the classic scripts `pt-demo.js`, `pt-chunk.js`, `pt-datasource.js`, `pt-state.js` unchanged, so **sign-in,
  tier detection, holdings sync (`/api/state`), sample portfolio and plan limits behave exactly as in v1**. A new version
  only needs a new `public/vN/` folder and a rewrite; everything in `core/` is reusable.
* Sign-in / sign-up / forgot password talk to `/api/auth/*` directly (no redirect to the old login page).
  Checkout and billing portal send `ret:"/v2"` so Stripe returns you to v2.
* The classic terminal links to v2 (button `V2`), and v2 links back (Me → Open the classic terminal) for the deep tools
  that are not rebuilt (DCF valuation, RRG rotation, breadth, OBOS, factor and capital-flow panels).

## Live prices (publish / subscribe)

`core/live.js` is the single poller; screens subscribe and repaint only the numbers that changed.

* Signed-in: `POST /api/free/quotes` (Alpaca IEX snapshots for US; Yahoo chart meta for HK/BK). Server keeps 4 s of
  per-symbol cache, so N users watching one ticker cost one upstream read per window. Client cadence: ~5 s market open,
  20 s pre/post, 2 min closed, paused when the tab is hidden, exponential back-off on errors.
* Several tabs on one device share one poller through `BroadcastChannel` (a leader polls, the rest listen).
* A true websocket is not used: Vercel functions are short-lived, and Alpaca's free tier allows one stream connection per
  account, which cannot be fanned out to browsers without a long-running server. If a persistent host is added, replace the
  endpoint with an SSE/WebSocket relay; `live.js` already isolates the transport.
* Sample portfolio: a local random-walk simulator drives the same UI.

## Caching (data that does not change per person)

* Browser: `core/cache.js` (IndexedDB, TTL, stale-while-revalidate) holds news (5 min), macro / mood / sectors (1–6 h),
  analyst view (3 h), FX (6 h), holdings history (10 min), the council result (3 h).
* Server (already shared, Supabase `pt_av_cache`): news 90 min, analyst card per symbol 24 h, ticker headlines 30 min,
  earnings calendar 12 h, per-language news translation 90 min.

## Analysts, price targets, events

`/api/free/street` returns, per symbol: rating mix (Buy/Hold/Sell), price target (mean; low/high when a provider supplies
them), recent headlines with a keyword tone, next earnings date. Providers, in order, each optional by env var:
`FMP_API_KEY` (price-target consensus: mean, median, high, low), `FINNHUB_API_KEY` (recommendation trends), else Alpha
Vantage `OVERVIEW` (mean target + rating counts, shares the 22-calls/day budget). **Without FMP/Finnhub keys the target
range (low/high) is not available and the UI says so; set `FMP_API_KEY` for full ranges.** Nothing is fabricated.

Events (`core/council.js buildEvents`): Fed decision (2026 dates), jobs report (first Friday, marked estimated), CPI
(mid-month, marked estimated), earnings (Alpha Vantage calendar). Each carries a lean in −1..+1:
earnings = 0.55·analysts + 0.45·media − run-up penalty; macro = 0.4·analysts + 0.35·media + 0.25·fear/greed.

## The Council (Outlook)

`core/engine.js` runs N simulated years (default 5,000; 10k/25k/50k selectable) for nine personas on the user's own
holdings with common random numbers, calm/stormy market regimes, event jumps shifted 30% toward the lean, persona rules
(tilts, cash policy, rebalance cadence, FOMO drawdown rule, vol targeting). The UI prints the real count, days and run
time. It replaced the old "1B Projection Lab", whose 1B was a design label and whose curves were hand-authored; nothing
is hard-coded now. Reasons per persona are rule-derived and translated; Premium adds an AI-written explanation
(`/api/ai/council`, validated numbers only, 30/day).

## Language

Every visible string is `t("English sentence", {vars})`; numbers, money, dates and chart axes use `Intl` for the chosen
language. 9 non-English languages (th, zh-Hans, zh-Hant, ja, ko, es, hi, vi, fr). News is translated server-side per
language. `node scripts/check-i18n.mjs` fails if any string is missing or placeholders differ;
`node api/_council.test.js` runs the same check plus engine tests.

Add a string: use `t()` in code, add it to `scripts/i18n-v2/keys.json` order is by `node scripts/check-i18n.mjs --json`;
append translations in `scripts/i18n-v2/extra.json` (`{"English": {"th": "...", ...}}`), run
`node scripts/build-i18n-v2.mjs && node scripts/check-i18n.mjs`.

## Not in v2 (still in the classic terminal)

DCF valuation tab, RRG rotation, breadth / OBOS, factor and capital-flow panels, 100 themes, admin cost page.

## v3 "Desk" (`/v3`)

A deliberately different layout on the same `public/core`: dense multi-pane trading desk (scrolling price tape, holdings table,
chart + analysts for the selected stock, news / events / markets, a Council strip), amber-on-black monospace, `/` to jump to
a ticker. On phones the panes become tabs. It reuses v2's dialogs (sign-in, add/import, AI analyst, account and plans), so
login, payments and translation behave identically; Stripe returns to the version you paid from (`ret:"/v3"`).
